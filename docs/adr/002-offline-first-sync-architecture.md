# ADR 002: Offline-First Architecture & Encrypted Local Work Queues

## الحالة (Status)
معتمد (Accepted) — تاريخ: سبتمبر 2026

## السياق (Context)
في البيئات الجامعية الواقعية وأثناء مسح كميات ضخمة من الشهادات الورقية في قاعات الأرشيف أو لجان الامتحانات، قد يحدث انقطاع مفاجئ لشبكة الإنترنت أو اتصال الخادم. لا يمكن بأي حال من الأحوال إيقاف العمل أو فقدان ما تم مسحه ومعالجته.

## القرار (Decision)
اعتماد معمارية **العمل غير المتصل أولاً (Offline-First)** مع الطوابير المشفرة محلياً:
1. **الطابور المحلي المشفر (Encrypted Local Queue)**:
   - تخزين الصور والنتائج المستخرجة وحالات المراجعة في قاعدة بيانات محلية مشفرة بمفتاح الجهاز.
   - وسم كل عملية محلياً بحالات واضحة: `local` / `pending` / `synced` / `conflict` / `failed`.
2. **سلطة الخادم للسجلات الرسمية (Server-Side Authority)**:
   - العمليات غير المتصلة لا تصبح رسمية نهائياً إلا بعد المزامنة وتأكيد الخادم.
   - حظر أسلوب "الكتابة الأخيرة تفوز (Last-Write-Wins)" على السجلات المعتمدة؛ يتم فض التعارضات على مستوى الحقل مع إشعار المستخدم والموافقة البشرية الصريحة.
3. **مقاومة انقطاع الشبكة**:
   - استئناف الرفع والمزامنة تلقائياً بمجرد عودة الاتصال باستخدام معرفات العمليات غير القابلة للتكرار (Idempotent Operation IDs).

## العواقب (Consequences)
- انعدام الفقدان الصامت للبيانات (Zero Silent Data Loss).
- استمرار موظفي الأرشيف في تصوير ومراجعة مئات الشهادات أثناء انقطاع الشبكة.
